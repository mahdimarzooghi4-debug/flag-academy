## اصل طراحی Curriculum

Curriculum پرچم فهرست درس‌ها نیست. واحد طراحی آن **Capability** است.

هر بخش زمانی Complete محسوب می‌شود که فرد بتواند کاری را انجام دهد و برای آن Evidence قابل دفاع تولید کند؛ نه صرفاً وقتی محتوا را دیده یا آزمون دانشی را گذرانده است.

## چرخه استاندارد هر Capability

**Diagnose → Learn → Practice → Mission → Feedback → Reflection → Replay → Evidence**

هدف Diagnose این است که اگر فرد از قبل Evidence معتبر دارد، آموزش غیرضروری کوتاه یا Skip شود.

اصل:
> Evidence Skip نمی‌شود؛ فقط آموزش غیرضروری می‌تواند Skip شود.

## Knowledge در برابر Competency

هر Capability دو لایه دارد:

1. **Knowledge Check** — فهم مفهوم
2. **Capability Mission** — اثبات استفاده از مفهوم در موقعیت واقعی‌نما یا واقعی

Knowledge Check وزن اصلی Flag Profile را ندارد.

## Artifact-based Learning

یادگیری باید Artifact تولید کند.

نمونه Artifactها:
- Problem Brief
- Interview Notes
- Insight Map
- Metric Tree
- Strategy Memo
- Prioritization Decision
- Experiment Design
- PRD / Spec متناسب
- Roadmap
- Stakeholder Memo
- Post-mortem
- Decision Log

هر Artifact باید به Mission، Outcome و Competency متصل باشد و صرفاً Portfolio نمایشی محسوب نمی‌شود.

## اصل شخصی‌سازی

مسیر دو نفر الزاماً یکسان نیست.

یک فرد ممکن است در Data قوی باشد و آن بخش را سریع‌تر عبور کند ولی در Stakeholder Alignment به Missionهای بیشتری نیاز داشته باشد.

اصل:
> استاندارد خروجی یکسان است؛ مسیر رسیدن می‌تواند متفاوت باشد.

## اصل زمان و استاندارد

> پرچم زمان حضور را استاندارد نمی‌کند؛ استاندارد شایستگی را استاندارد می‌کند.

بنابراین مدت مسیر برای افراد می‌تواند متفاوت باشد، اما Evidence لازم برای عبور از Gate یا دریافت مسئولیت نباید برای افراد مختلف سلیقه‌ای تغییر کند.
