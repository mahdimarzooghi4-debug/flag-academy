# 35 — Blended Learning Product Model

**وضعیت:** FINAL  
**تاریخ تثبیت:** 2026-10-04

## تعریف

> **Parcham OS سیستم عامل یک آکادمی توسعه رهبری است که آموزش کلاسی، تمرین، شبیه‌سازی، تجربه واقعی و Evidence را در یک مسیر واحد به هم متصل می‌کند.**

اصل کلیدی:

> **کلاس محل اصلی آموزش است؛ Simulator مکمل کلاس برای Practice، Transfer و Assessment است.**

## 1. Blended Learning Model

زنجیره اصلی:

**Class → Practice → Simulator → Feedback → Reflection → Real Application → Evidence → Flag Profile**

Simulator جای کلاس را نمی‌گیرد.

کلاس برای آموزش Structured Knowledge و Mental Modelهاست؛ Simulator برای سنجش و تمرین انتقال آموخته‌ها به موقعیت‌های مبهم و واقعی‌تر است.

اصل:

> **Class teaches the model. Simulator tests transfer.**

## 2. سه لایه تجربه یادگیری

### LEARN
- Class
- Instructor
- Reading / Content
- Example
- Knowledge Check
- Assignment

هدف: فهم مفهوم و مدل.

### PRACTICE
- Workshop
- Case Study
- Guided Exercise
- Group Exercise
- AI Tutor
- Feedback

هدف: توانایی استفاده از مفهوم با کمک و بازخورد.

### PROVE
- Simulator
- Assessment Mission
- Real Project
- Ownership Trial

هدف: اثبات توانایی استفاده مستقل از Capability در شرایط واقعی‌تر و با کاهش کمک.

## 3. Candidate Home

Candidate Home باید همزمان دو سؤال را پاسخ دهد:

> **الان چه چیزی باید یاد بگیرم؟**

و:

> **الان چه چیزی باید اثبات کنم؟**

Home می‌تواند شامل Classهای آینده، Pre-work، Assignment، Practice، Simulator، Reflection، Gate State و Next Experience باشد.

Course Completion Percentage به‌تنهایی مدل اصلی پیشرفت نیست.

## 4. Capability as Curriculum Unit

Capability همچنان واحد اصلی Curriculum باقی می‌ماند، اما هر Capability می‌تواند Learning Journey شامل این اجزا داشته باشد:
- Classes / Sessions
- Workshops
- Case Studies
- Assignments
- Practice Missions
- Simulator Missions
- Reflection
- Replay

مثال Product Strategy:
- Class 1: Strategy ≠ Goal
- Class 2: Where to Play / How to Win
- Workshop: Strategic Trade-offs
- Case Study: Everything Strategy
- Assignment: Strategy Memo
- Practice Mission: Growth vs Profit
- Simulator: Strategy Under Constraint
- Reflection
- Replay

## 5. Classroom Features

Parcham OS باید قابلیت‌های Academy/Learning Management زیر را به‌صورت First-class پشتیبانی کند:
- Course/Class definition
- Session schedule
- Instructor assignment
- Attendance
- Pre-work
- Learning materials
- Video / recording / summary
- Assignment
- Submission
- Knowledge Check / Quiz
- Group exercise
- Discussion / Q&A
- Instructor feedback
- Class completion

## 6. Instructor Role

Instructor یک Role مستقل و First-class است.

Instructor Workspace باید بتواند:
- Classهای خودش را ببیند
- Roster را ببیند
- Session را مدیریت کند
- Material منتشر کند
- Assignment تعریف کند
- Submissionها را بررسی کند
- Feedback بدهد
- Learning progress را ببیند

اما:

> **Instructor Feedback، Attendance و Class Completion به‌صورت خودکار Capability Proven ایجاد نمی‌کنند.**

Learning Completion از Evidence of Capability جداست.

## 7. Cohort Model

Cohort یک مفهوم First-class در Academy است.

نمونه:
**PM Flag Cohort — Winter 2026**

Cohort شامل:
- Candidates
- Instructors
- Schedule
- Classes
- Groups
- Assignments
- Workshops
- Simulation Windows
- Assessment Camp
- Milestones

Academy هم Journey فردی دارد و هم تجربه گروهی.

## 8. Simulator as Class Complement

Simulator می‌تواند مستقیماً به Class یا Capability متصل شود.

مثال:
- Class: Prioritization
- Simulator: Executive Favorite

پس از Simulator، Instructor می‌تواند Cohort Debrief انجام دهد بدون اینکه Assessment-sensitive hidden targets را افشا کند.

Debrief می‌تواند روی Patternهای عمومی تمرکز کند:
- Strategy abandonment
- Authority pressure
- Cost of Delay
- Evidence use
- Trade-off quality

## 9. Learning vs Evidence Boundary

سه نوع State باید جدا باشند:

### Learning Completion
فرد آموزش را گذرانده است.

### Practice Performance
فرد در تمرین هدایت‌شده عملکردی نشان داده است.

### Proven Capability
Evidence معتبر و مستقل برای Capability وجود دارد.

اصل:

> **کلاس را کامل کرده ≠ Capability را اثبات کرده.**

## 11. Revised Product Positioning

Parcham OS نه LMS صرف است و نه Simulator صرف.

تعریف نهایی:

> **Parcham OS سیستم عامل یک آکادمی توسعه رهبری است که کلاس، تمرین، شبیه‌سازی، تجربه واقعی و Evidence را به یک Journey واحد متصل می‌کند؛ کلاس محل اصلی آموزش است و Simulator نقش مکمل برای Practice، Transfer و Assessment دارد.**
